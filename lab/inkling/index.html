How this actually works — the whole network, in one screen

Every drawing is downsampled to an 8×8 grid — 64 numbers between 0 (blank) and 1 (full ink). That's the entire input. From there it's the plainest network there is:

Forward: a₁ = tanh(W₁x + b₁), then ŷ = softmax(W₂a₁ + b₂). Loss: cross-entropy against the label you gave it. Backward: the standard chain rule — δ₂ = ŷ − y, then δ₁ = (W₂ᵀδ₂) ⊙ (1 − a₁²) — with every W and b nudged by −η·∂L. Pressing Train adds your sample to everything taught so far and re-runs several passes over all of it, so earlier letters don't get forgotten as new ones arrive.

Look inside the network, in detail

Your drawing becomes 64 pixel values, every one of which connects to all 18 hidden neurons — the network's one and only hidden layer — which in turn connect to 26 output neurons, one per letter A–Z. Step 5's 18 tiles are those 18 hidden neurons: each has learned to look for one pattern of ink across your drawing grid — its receptive field. A tile's border color is that neuron's bias; its interior is its 64 input weights reshaped back into the 8×8 drawing grid, rose where a pixel excites that neuron and blue where it inhibits it. The larger heatmap next to the tiles is the next layer's weights: one column per output letter, one row per hidden neuron (same order as the tiles), again rose/blue for how much that neuron pushes toward or away from that letter. Both update live as you train.

The QR code is quantized — it's not quite the full network

Total parameters: 64×18+18 hidden, 18×26+26 output = 1,664 numbers. At 8 bits each that's 1,664 bytes — genuinely too dense to fit in one QR code at this network's size, confirmed directly against the real QR library rather than assumed. So the QR code above compresses every weight and bias down to 4 bits each first (832 bytes) — enough to fit comfortably, but a real, permanent loss of precision compared to the exact numbers this network is actually using right now. Scanning it back in reconstructs a network that's close to this one, not byte-identical to it. The "copy full-precision weights" box further down is the exact, lossless version of the same numbers, if that difference ever matters more to you than a QR code's convenience.
