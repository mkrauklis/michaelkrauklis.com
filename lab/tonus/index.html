How this actually works — the real math behind each model

Every dataset here starts from a seeded pseudorandom generator (mulberry32) — the same number in, the same points out, every time, which is what makes the seed alone enough to reproduce a dataset in a shareable link without ever sending the points themselves. Every model is evaluated across the same real 100×100 grid spanning [-1, 1] on both axes to paint the background — 10,000 real predictions per render, not an interpolation.

Linear Regression, as a classifier

Ordinary least squares fit directly, in closed form — no gradient descent, no iteration. Three unknowns (a bias and one weight per axis) means the normal equations are just a 3×3 linear system, solved exactly with Gaussian elimination:

(XᵀX) w = Xᵀy

The fitted line w₀ + w₁x₁ + w₂x₂ is thresholded at 0.5 for a hard class call, but it was never trained to produce probabilities — this is the one model here that's solving a different problem (minimize squared error) and only being repurposed as a classifier, which is exactly why it tends to fail hardest on anything non-linear.

Logistic Regression

The same linear score, this time passed through a sigmoid and actually trained to minimize cross-entropy loss — real gradient descent, one step per epoch, average gradient over every point:

ŷ = σ(w₀ + w₁x₁ + w₂x₂)

Because the gradient of cross-entropy loss with a sigmoid output collapses to the same clean (ŷ − y) form Inkling's own network uses for its output layer, the update rule here is genuinely the same piece of math, just for a 3-parameter model instead of a 64→18→26 network.

Linear classifier, hinge loss

Trained with the Pegasos algorithm (Shalev-Shwartz, Singer & Srebro) — stochastic subgradient descent on the hinge loss with L2 regularization, one point at a time, learning rate 1/(λt) shrinking as training proceeds. Deliberately not called "SVM" outright — a true support vector machine is defined by its dual formulation and support vectors; this is a linearly-parameterized model trained to the same max-margin objective, which produces a similar-looking boundary without being the same algorithm.

k-Nearest Neighbors

No training step at all — the "model" is just the stored points. To classify anywhere, find the k closest real data points by plain Euclidean distance and take the fraction of them in class 1 as the confidence. It's the one model on this page that genuinely never generalizes past its own data — turn k down to 1 and watch the boundary trace every single point's own tiny neighborhood.

Gaussian Naive Bayes

The one properly probabilistic model here — everything else either fits a boundary directly or votes; this one models each class's own distribution and applies Bayes' rule. Each axis, within each class, is treated as an independent Gaussian (mean and variance estimated directly from that class's points); a new point's class probability comes from the ratio of the two classes' likelihoods, weighted by how common each class actually is in the data:

P(y=1∣x) ∝ P(x∣y=1)·P(y=1)

Because both classes are Gaussian, this ratio collapses into the same sigmoid shape logistic regression produces — but arrived at from a completely different starting assumption (model the data, not the boundary), which is why its boundary bends where logistic regression's stays straight whenever the two classes' spreads differ.

Random Forest

A real bootstrap-aggregated ensemble — each of the configurable number of trees is grown from a fresh random resample (with replacement) of the actual dataset, and each tree is built greedily: at every node, try every possible axis-aligned split on both x1 and x2, keep whichever split most reduces Gini impurity, and recurse until the max depth or a pure/tiny node stops it. A point's final confidence is the plain average across every tree's vote — which is exactly why the boundary is stepped and orthogonal rather than smooth: every individual tree can only ever cut the space with straight horizontal or vertical lines.

Multi-Layer Perceptron

The one model here trained with real backpropagation through more than one layer, via TensorFlow.js so the actual matrix math runs accelerated in your browser (WebGL where it's available) rather than in a hand-written loop. 1-4 hidden layers, 2-64 neurons each, your choice of ReLU/sigmoid/tanh activation, trained with the Adam optimizer against binary cross-entropy loss for the chosen number of epochs. Known simplification: unlike Afterimage's decoder (see that tool's write-up for why), this doesn't check for or fall back from low-precision WebGL — at this network's tiny size a precision issue hasn't shown up in testing, but if a training result ever looks visibly wrong, that's the first thing to suspect.

The share link and QR code

The dataset type, PRNG seed, point count, selected model, and every one of its hyperparameters are packed into a small byte payload, base64url-encoded into this page's own URL — the same scheme Echo State and Inkling already use for their own share links. A drawn-by-hand or uploaded dataset has no seed to replay, so its actual points are quantized (one byte each for x1/x2, one for the label) and packed in afterward instead — still small enough to fit comfortably in a QR code even at a few hundred points. The QR itself is generated by the same vendored qrcode.min.js library already sitting in those two tools' own folders.
